# 摸鱼鱼池 (moyu-pond)

一张会动的锦鲤池塘桌面壁纸，**接真实天气**：外面下雨池子就下雨，天阴水色就发灰，风大浪就大，天冷鱼就往深水沉。当前是**网页原型**阶段，打包成桌面应用留到下一步。

## 直接打开

- 最简单：双击 `index.html`（`file://` 也能跑，104 项自检全通过）
- 或起个本地服务：`python -m http.server 8765`，访问 `http://127.0.0.1:8765/`

带参数：`?debug=1` 左下角显示帧率；`?fresh=1` 忽略已保存的设置回到默认。

天气用 Open-Meteo，**免费、不用申请 key**，断网也只是退化成本地模拟，不会卡住启动。

## 操作

| 动作 | 效果 |
|---|---|
| 在鱼池上点击 | 投食，附近的鱼聚过来抢食并打涟漪 |
| 鼠标划过鱼群 | 默认的"绕行让路"：鱼往侧边一让，从你手边绕过去，不是掉头就跑 |
| `Ctrl` + `,`，或点右下角"设置" | 开关设置面板 |
| `Esc`，或面板顶栏的 ✕ | 从设置面板回到卡片的天气界面 |
| `F9` | 切帧率显示 |

右下角是一张毛玻璃卡片：时间、日期、天气、三天预报、下班倒计时都在这，点"设置"就地展开面板。面板自带顶栏（✕ 返回 + 两个标签页），所以**不会出现点进去出不来的情况**。

面板分两页：**鱼池**（天气 / 画面 / 桌面信息）和 **我的锦鲤**（[画板](#我的锦鲤画板)）。拆页不是为了好看——画板比设置高一倍，两样塞在一页里只能拖滚动条，而右侧那条灰白实心杠很难看；拆开之后每页都能在屏幕里装下，滚动条就没了（真的小到装不下时才内部滚动，滚动条是隐藏的，底下留一道渐隐当提示）。

设置项存在 `localStorage`，只在本机。

### 鼠标互动（设置里四选一）

| 档位 | 行为 |
|---|---|
| 靠近绕行（默认） | 鱼进入光标半径后往侧边让，方向在进入的那一刻定下来，不会左右抖 |
| 点击投食 | 点一下撒 4~6 粒饵，附近的鱼聚过来 |
| 靠近惊散 | 受惊掉头猛逃，游速拉满 |
| 关闭 | 鱼完全不理光标 |

让路的侧偏方向是**进入光圈时一次性锁定的**（`Fish.dodgeSign`），否则每帧按当前朝向重选一次会在中线附近来回翻转、等于原地不动。

## 天气联动

走 [Open-Meteo](https://open-meteo.com/)（`api.open-meteo.com/v1/forecast`），**免费、不用 key、允许跨域**，所以双击 `index.html` 也能拉到真实天气。当前天气和三天预报是一次请求拿全的，每 30 分钟刷一次、8 秒超时；拉不到就先退回 localStorage 里上一次的成功结果（在 30 分钟内算数，不标离线），退回不了才按"节气 + 纬度"编一份本地模拟（同一天永远同一个结果，不会每秒跳一个天气），卡片上标"离线模拟"。

这些全在 `Weather.Station` 里收口：`start(cb)` 开一个 5 分钟的巡检（要不要真拉由 TTL 决定），`setCity()` 换城市，`snapshot(now)` 给 HUD 一份渲染好的小结构，**`env` 永远有值** —— 所以主循环里可以无条件取 `env()`，不用到处判空。

设置面板可以搜城市（走 `geocoding-api.open-meteo.com`，中文名直接搜），默认武汉。

WMO 天气码映射成中文描述和强度，之后导出一组系数驱动画面（`Station.buildEnv()`）：

| 系数 | 作用 |
|---|---|
| `light` / 色调 | 烘进背景缓存：阴天压暗压灰、晴天提亮回暖，重烘一次就够，不占每帧 |
| `rain` / `snow` | 雨丝、雪片粒子；落到水面打涟漪 |
| `fog` | 薄雾层浓度 |
| `wind` → `chopK` / `swayK` / `rippleRate` | 风大：水面波动更猛、水草摆得更厉害、随机涟漪更密 |
| `causticK` | 云厚就压暗水面光斑 |
| `fishSpeed` / `fishDepth` | 温度低：鱼游得慢、往深水沉 |

## 我的锦鲤（画板）

设置面板里嵌着一块画板，可以直接捏出好几条锦鲤放进池子：

| 控件 | 作用 |
|---|---|
| 身体轮廓 / 尾部长度 | 改鱼形本身（不是拉抻位图，见下） |
| 画笔 / 底色 | 8 种花纹色 + 5 种鱼身底色 |
| 笔头 / 橡皮 / 翻转 / 清空 / 随机花纹 | 画、擦、左右镜像、一键出斑 |
| 名字 | 最多 16 字，留空自动挑一个（小旦 / 粉黛 / 明月…），也能"随机起名" |
| 放入鱼池 | 提交这条鱼，立刻烘图集并让鱼群用上（**不重建鱼群**，观感是新鱼入池） |
| 我自定义的锦鲤 | 画廊，最多 8 条：点一条继续改，× 就从池中删掉 |

自定义鱼**总共**只占鱼群的约 9%（不是每条 9%），捏了好几条就在它们之间均分 —— 否则越画池子越像自己画的。删掉一条会把它的图集真的释放掉（一条约 2.5MB，攒 8 条就是 20MB），画稿本身留在本地，随时能重建。

存档在 `localStorage` 的 `moyu-pond:koi:v2`（老版本的单条 `:v1` 会自动迁移过来）。关掉"我的锦鲤"总开关只是让鱼群不选它们，图集还留着，随时能再打开。

### 鱼形是算出来的

轮廓不走位图，也不走"几段贝塞尔拼一拼"，而是**半高剖面采样**：

```
profile(u) = sin(π · u^1.45)^0.65      u=0 尾柄、u=1 吻端
```

`k=1.45` 把最宽处推到 u≈0.62（锦鲤的肩在身体偏前），`p=0.65` 决定胖得有多"满"，尾柄段再给一个 0.26 的下限，免得身体收成尖、尾鳍没地方接。有了这个函数，`身体轮廓` 只是乘一个 1 倍率、`尾部长度` 只是改尾柄位置，鱼形永远连得上，不会出现靠自己试贝塞尔控制点那种"调了尾长腰跑偏"的事。眼睛和胸鳍都按**当地的**半高定位，不然瘦鱼的头收窄后眼睛会挂到身外去。

尾巴不是单独画的一坨：尾鳍是半透明膜 + 7 条放射鳍条，涂色会被裁进包括尾鳍在内的整个鱼形，然后再把鳍用底色盖回 42% —— 图案落在鳍上会自然变淡，像真的半透明鳍。

### 涂色为什么要分两层

`raw` 离屏画布存你真正画下的每一笔（包括出界的），显示用的 `ink` 由 `raw ∩ 鱼形mask` 合成。所以**出界的笔迹不会脏在预览上**，反过来拖动轮廓滑杆时图案也能按新鱼形重新裁一遍。代价是每落一笔要合成一次 560×200，实测无感。

> 轮廓是**用 Path2D + 采样算出来的**，不是加载 PNG。因为 `file://` 下的图片算跨域，会把 canvas 污染掉，一旦污染 `toDataURL` 直接抛 `SecurityError`，存不下画稿。

## 画面是怎么搭的

从下往上，全部在一张 Canvas 上：

1. **池底** `assets/pond_base.png` —— AI 生成的水彩底图，经过平场校正、柔化、水色调色、高光压制、去水印
2. **天气光照** —— 和池底、水色、暗角、水下植物一起烘成一张静态缓存，天气变了才重烘
3. **水面波动（扫描线折射）** —— 把背景按行分带、每带横向错位，水下景物随波缓缓扭动
4. **池底投影** —— 鱼身下方那团影子，单独一趟先画完（所有影子都在池底，本来就在所有鱼的下面）
5. **锦鲤** —— 5 种内置花色 + 最多 8 种自己画的，按深度分三档（清晰 / 微糊 / 很糊），越深越小越淡
6. **水面光斑** —— 程序化 ridged noise 焦散图，缓慢平移
7. **涟漪** —— 扩散的残缺圆弧（亮边 + 暗内圈），鱼浮头、点击、雨雪落水、环境随机都会触发
8. **波纹光带** —— 预烘的正弦 tile，两层不同速度方向平铺，亮带慢慢淌过水面
9. **荷叶荷花** —— 压在鱼上面，所以鱼会从叶子底下钻过去

鱼的摆尾不是逐帧切片：启动时把「每种鱼 × 3 个水层 × 16 个摆尾相位」预烘成一张图集，运行时每条鱼只有一次 `drawImage`。

### 游姿

只调"往哪儿游"是不够像的 —— 匀速滑行的鱼最假。下面三条每条都是几行标量运算，不增加一次 `drawImage`：

| 改动 | 做法 |
|---|---|
| **爆-滑步态** | 真锦鲤是"抖一下尾给一股推力，然后伸直身体滑一段"。相位 `gait` 取 `sin⁶`，半周期里只有约 3 成时间在推：瞬时速度在 0.85~1.35 倍之间起伏，平均值不变；摆尾频率也挂在同一个节奏上（滑行时尾巴几乎停住） |
| **体轴弯曲** | 转弯时整条鱼会先弯成弧形。用**一次剪切**近似：`y' = y + bend·x` —— 头在原点不动、越往尾巴挪得越多，正好是一条鱼的弯曲。一次 `transform`，不多画一笔 |
| **侧滑** | 渲染朝向 `pose` 追不上真正的航向 `angle`（一阶滞后），于是急转的瞬间身体还指着来路，像被水"蹭"过去一样；同时随角速度给一点横滚，侧影变窄 |

> 弯曲的系数是"看着舒服"而不是物理精确的：池子里 60px 的小鱼要能以 1.15 rad/s 掉头（不然半天转不过身），真按 `R = v/ω` 换算曲率，半径比体长还短，鱼会弯成一个圈。所以只做线性一阶近似并把量级压小 —— 巡游时基本是直的（实测 `|bend|` 中位数 0.068），只有真急了（躲鼠标、抢食）才明显弯成弧（0.14）。

### 碰撞体积

鱼的身体是一个**沿体轴的椭圆**（半长轴 0.42·体长，半短轴 0.42·体长×0.38，跟着体长走），两条深度差 >0.2 的鱼不算撞上（它们本来就不在同一层水里）。

判据放在"我自己的体坐标"里做：`along` 是前后、`lat` 是左右，对方也近似成同尺寸的椭圆，两个椭圆相加就是判据本身。然后挑**更省力的那一轴**推开：

- 并排 → 横向擦身（最常见，真鱼也是这么过去的）；
- 顶牛 → 顺着体轴前后分开，并且**在后面那条收油门**（`speed *= 0.94`），否则它会一路顶着前面的鱼推过去。

软分离（boids 那部分）的半径同时从 1.9·体长收到 1.15·体长 —— 以前那个半径太大，鱼群会散得过分；现在由硬碰撞兜底，鱼群反而贴得更近、更像一群鱼。实测 2345 对邻居里 0 对穿模，最近的一对也有 0.27 个体长的间距。

### 池塘深浅

`cfg.pondDepth`（设置面板「画面 → 池水深浅」，0.35~1.00，**默认 0.60**）把整列水按比例压扁：`depthNow = 天生深度 × pondDepth + 天气偏移`。

拖滑杆立刻生效，因为体长是每帧按 `depthNow` 插值的（不是出生时定死的）：拖到 0.35 时中位体长 44px，拖回 1.00 是 36px。副作用是**"很糊"那一档基本用不上了**（阈值在 0.70，而 0.60 的池子最深处也只有 0.60）——这本来就是"水浅"的意思：看得更清。

顺带：水变浅把体长区间压窄了，"塘主"那条大鱼跟中位数的差距会被压到 1.5 倍以内，看着不压场。所以塘主改成**只从底子大、位置浅的那批里挑**、放大 1.45~1.85 倍；抽不中的话（一池百来条也有几个百分点的概率）`syncPopulation()` 会把最靠水面、底子最大的那条提成塘主 —— 保证每池都有。

### 池底投影

每种鱼烘**一张**中等模糊的深色剪影（80px 体长，不是摆尾图集那个 140px），运行时靠三件事表达远近（gap = 离池底的距离，0 贴底、1 贴水面）：

| gap | 偏移 | 大小 | 浓度 |
|---|---|---|---|
| 0（贴底） | 2.5px | ×1.04 | 0.26 |
| 1（贴水面） | 32px | ×1.34 | 0.05 |

光从左上来，所以偏移方向是右下（×0.62, ×0.86）；旋转和弯曲都跟着本体走，转身时影子不会脱开。**所有影子先画完再画鱼** —— 它们投在最下面那一层，混着画会让先出现的鱼压住后一条鱼的影子。

> **烘小是有原因的**：软件渲染下 `drawImage` 的开销按**源**面积算，源图烘成 174×104 而实际只画到 46×26 时，等于每帧替每条鱼读 1.8 万像素再缩掉 —— 实测这一层吃掉 35% 的帧率（48 → 31 fps），缩到 80px 之后回到 36 fps。所以又把它接进了降级阶梯：`autoDrop > 0.6` 时整层让位（`<=0.45` 才回来，避免在阈值上忽有忽无），低画质档直接不做。软件渲染 1920×1080 / 144 条鱼回到 **46.8 fps**（跟没有影子时一样），GPU 下 238 fps、`drop` 为 0，影子照画。

### 水面波动

三件事共用同一个高度场 `waveSlope(y, t)`（三条正弦叠加），所以水和浮在里面的东西是**一起**动的：

- **扫描线折射**：背景按行分带，每带横向错位 `amp * waveSlope(y, t)`。关键是**波长比屏幕还长**——相邻带的位移差极小，看不出阶梯，只有整体的涌动。分带数跟画质档走（高 26 / 中 14 / 低 不折射），掉帧或把"水面波动"拉到 0 就退回一次整张拷贝。
- **波纹光带**：两层 tile，速度和方向都不同，用来打破周期感。
- **物体随波**：鱼和浮叶按同一个高度场做几像素位移。

> 光带一开始是手写 `for` 循环贴砖的，1920×1080 下两层要画满"屏幕 + 一块砖"，约 **1180 万像素/帧（5.7 个屏幕）**，软件渲染实测 **51 → 33 fps**。改成 `createPattern` + 一次 `fillRect` 只填屏幕本身，外扩全省掉，回到 46 fps。这条有断言守着（数 `fillStyle instanceof CanvasPattern` 的 `fillRect` 次数）。

## 自检结果

- `node tools/test.js`：**104 项**全通过，`file://` 和 HTTP 两种方式各跑一遍都是 104/0
  - 跑之前记得先把本地服务**常驻起来**（后台进程），不能只在前一条命令里 warm up：一次性起的 `python -m http.server` 会随那条命令一起结束，Chrome 拿到的是 `ERR_CONNECTION_REFUSED`，症状是 `__moyu is not defined` 而不是"测不过"
  - 覆盖：素材、鱼群行为、绕行/惊散对照、**游姿（步态/弯曲/侧滑）**、**碰撞体积**、**池塘深浅**、**池底投影（含降级让位）**、涟漪波列与折射、装饰避障、乌龟蝌蚪蝴蝶、场景氛围、**水面波动**、**天气与毛玻璃卡片**、**面板分页与返回**、**画板与自定义锦鲤**、时钟倒计时、响应式、全程无 JS 报错
  - 有几条断言是踩过坑才写成这样的：
    - 惊散用"累计行程"而不是"离起点距离"（绕圈的鱼离起点可能没变远）
    - 投食数量做成同步断言；点击那条还要先把鱼群整段摘走再点，否则落在鱼嘴边的饵几十毫秒内就被吃光，读到 0 会被误判成"没投食"
    - 折射、波纹光带的调用计数都要**按住 `autoDrop`**——软件渲染下帧率会触发自动降级，降级把这些整层跳过是设计行为，不该被当成 bug
    - 光带改成 pattern 之后专门加了一条计数断言，防止哪天改回逐块贴图把性能又吃回去
    - 画板那条"花纹只画在涂色层"从"参考层几乎没有深色像素"改成**前后逐像素差分**：参考层现在带鱼鳍、鳍条和眼睛，不再是一片白了，原来那套判断会误报
    - 窄屏面板那条得先把视口压到 430（比面板 420 还窄）才有意义，1024 宽下面板压根没被挤到，是条永远绿的假断言
    - 有一条断言里带副作用（`apply()` / `remove()`），所以**只能求值一次**再判断。一开始写成 `check(名, await ev(...).then(...), await ev(...))`，等于同一条鱼被放进去两次、删掉两条
    - 面板分页之后画板搬进了第二页，而折叠用的是 `display:none` —— **`display:none` 的元素 `getBoundingClientRect()` 全是 0**（`visibility:hidden` 却仍有布局，之前测试之所以能跑就是这个区别）。所以画板那一整段要先 `HUD.openTab('koi')` 切过去再量，跟人手点一下一样
    - 面板"不用滚动条"这条直接量**每一页自己的** `scrollHeight <= clientHeight`：两页拆开才装得下，合在一起是必然超的
    - 影子/折射这类**会被降级阶梯拿掉**的层，数调用次数时都得按住 `autoDrop`，否则测的是"降级后的同一件事"
    - 数"一帧里影子都在鱼之前"时，帧边界不能拿背景那次 `drawImage` 当分隔符：开着折射时背景是分 26 带画的，一帧里有 26 次。把无关符号滤掉只看 S/F，一帧就是"一段 S 接一段 F"
  - 折射有一条**像素级断言**：同一块背景画两遍（一遍不折射），比较"环带"和"远处对照区"的通道差，环带必须显著更大。`file://` 下图片算跨域、canvas 被污染读不了像素，这条会标记为 skipped 跳过（应用本身不读像素，照常运行）
- `python tools/qa.py <截图> <参考图>`：与参考图对比（参考图也可以走 `MOYU_REF` 环境变量；脚本里的 `REF_BOX` 是"纯水"取样区，换参考图要重框）
  - 水色：色相偏差 **2.8°**、饱和度差 0.03~0.04、明度差 0.05、三通道平均差 7.3~8.4/255（4 次采样）
  - 鱼：体长中位数比参考图 **0.77~1.11 倍**、密度比 **1.31~1.77 倍**（4 次采样）
  - 这两组数字都带**前提**，换条件就会动，读的时候得连着前提一起读：
    - **水色跟着当时的真实天气走**。上面的 0.05 / 7.3~8.4 是阴天测的（当天云量 100%、25.9°C、WMO 3、白天）——阴天的色偏会烘进背景缓存，比晴天测出来的数大。当初记的"明度差 0.02 / 通道差 3"是晴天那一次的值
    - **密度比跟着池塘深浅走**。检测器只数得清亮色的近水面鱼，深水鱼它数不到（脚本里也注明了这是下限）。把 `pondDepth` 从默认 0.60 推回原来的 1.0，同一池 144 条鱼，密度比就从 1.31~1.77 掉回 **1.07**、体长比 0.94。所以密度比变大是"被数到的鱼变多"，不是"鱼变多"
  - 就算前提一致，这两个比值也有采样噪声：检测器会把靠得近的鱼合并成一个连通块，鱼越密越饱和，所以只能当趋势看，最终判断靠肉眼比对比图
- `node tools/perf.js <url>`（1920×1080 / 144 条鱼）：
  - `MOYU_GPU=1` 真 GPU 光栅化：**240 fps**（撞到 rAF 上限，最坏帧 5ms，余量很大）
  - 默认纯软件渲染（`--disable-gpu`，最坏情况）：**46 fps**，此时自动降级已把扫描线折射、涟漪折射、水面光斑砍掉，波纹光带也淡到几乎为零——但**一条鱼都不减**
- `node tools/mem.js [url] [布置表达式]`：常驻纹理内存 **40.2MB**（素材从 11MB 压到 3.6MB、源图不再保留；其中摆尾图集 15.5MB、鱼的剪影只占 0.1MB）
  - 画一条自定义锦鲤 **+2.4MB**（实测：两条 15.5→20.2MB 的摆尾图集），算满 8 条约 59MB。所以只在进池时烘、删掉真的释放

## 性能与内存是怎么压下来的

第一版逐帧做切片摆尾 + 全屏 soft-light 混合，无 GPU 时只有 **2.9 fps**。改法：

| 手段 | 效果 |
|---|---|
| 底图 / 水色 / 暗角 烘成一张静态缓存 | 每帧从"缩放绘制 + 两次全屏混合"变成一次位图拷贝 |
| 摆尾预烘成图集（5 种鱼 × 3 水层 × 16 相位） | 每条鱼从 16 次 drawImage 降到 1 次 |
| 荷叶的模糊投影烘进缓存 | 去掉每帧 13 次 `ctx.filter` |
| 焦散图预放大到使用尺寸 | 平铺时不再做双线性缩放 |
| 素材降采样到实际显示尺寸（鱼 340px、装饰 420px） | 资源 11MB→3.6MB，常驻内存 91MB→43MB |
| 图集烘完就释放源图 | 省掉 22MB 再也用不上的纹理 |
| 鱼的剪影只烘一张 80px 的（不烘三档、也不用 140px） | 软件渲染下 `drawImage` 按**源**面积收费，这一层从 35% 的帧开销降到 ~10%，5 种鱼一共 0.4MB |
| 池底投影接进降级阶梯（>0.6 让位、<=0.45 回来） | 弱机自动回到没有影子时的 46.8 fps，强机照画 |
| 波纹光带用 `createPattern` 一次铺满，不手写贴砖 | 省掉 5.7 个屏幕的外扩像素，软件渲染 33→46 fps |
| 天气光照烘进背景缓存 | 每帧零成本，只有天气变了才重烘一次 |

### 掉帧时的降级顺序

帧率掉到 45 以下，`autoDrop` 往上涨（0→1，涨得慢落得也慢），按这个顺序让路：

1. 波纹光带砍到单层并淡出（`autoDrop` 一涨就开始）
2. **池底投影整层让位**（>0.6 关、<=0.45 才回来，避免抖动）
3. 扫描线折射退回一次整张拷贝
4. 涟漪折射、水面光斑整层不画
5. 雨雪粒子隔一个画一个

**任何时候都不会自动减鱼**——鱼群数量突变比掉几帧难看得多。恢复流畅后逐级加回来。

## 已知的取舍

- 素材是 AI 生成的，风格接近参考图但不是同一套；换分辨率时底图会被放大，4K 屏上会偏软
- 水下植物层是平铺的，虽然做了镜像翻转打散重复，但仔细看仍能看出周期；浓度可以在设置里拉到 0 关掉
- 扫描线折射是**分带近似**，不是真逐像素折射：带数跟画质档走，站得极近盯着看理论上能发现带的边界（实测看不出来，因为波长比屏幕还长）
- 鱼群密度靠"帮派锚点 + 分离半径"调出来的，改数量滑杆时松紧度不变，但群体形状会变
- 碰撞用的是**同尺寸椭圆相加**的一次判据，不是真几何求交：两条鱼斜着贴很近时会有几毫秒的擦碰才分开（实测 2345 对里 0 对穿模，最深的擦碰 0.17）
- 池塘调浅之后最深处也到不了 0.70，摆尾图集里"很糊"那一档基本派不上用场 —— 这是"水浅"的必然结果，不是坏了
- 天气走 Open-Meteo 的**免费无 key** 接口，限流是对方说了算；被限流或断网时会先退回上一次的成功结果（30 分钟内算数），再退回按"节气 + 纬度"编的本地模拟（卡片上标"离线模拟"），不会白屏也不会卡住启动
- 天气的城市搜索要联网；搜不到就用当前坐标，不会把已存的城市清掉
- 离线的假天气只保证"看起来像那么回事"：温度按节气和纬度算正余弦，天气码是同一个整数散列表出的，同一天必得同一个结果（刻意不做成每秒随机的），但别拿它当预报用
- 画板捏的是**花纹 + 体型两条参数**，不是自由改轮廓：`身体轮廓` 和 `尾部长度` 只能在这一族鱼形里调，想画别的形状得改 `profile()`
- 一条自定义鱼约 2.5MB 常驻纹理（份摆尾图集）。上限 8 条 = 约 20MB，所以只在**进池**时才烘，删掉就释放
- 设置面板比卡片宽（420 vs 320），是锚在右下角向左长的；窄屏会自己收窄到视口内
- 面板拆成"鱼池 / 我的锦鲤"两页，代价是**同一时刻只看得到一页**；两页分别都量过能在 1280×720 里装下，真装不下时（比如 600px 高的窗口）页内还是会滚，但滚动条是隐藏的，只留底部一道渐隐当提示
- 体轴弯曲只是一次**线性剪切**（线性函数来近似真实的后行波），急转超过 90° 时这个近似会有点"折纸感"；不过同时还有尾鳍在摆，实际看不太出来
- `file://` 下图片算跨域，canvas 读不了像素。所以画板用程序化轮廓（不是 PNG）、折射那条像素级断言会 skipped——应用本身不读像素，照常运行
- 桌面图标压在鱼池之上需要挂到 Windows 桌面层，这一步在打包阶段做；届时鼠标点击会被桌面图标层吃掉，要改成轮询光标位置来做互动
